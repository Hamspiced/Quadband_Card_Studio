# Preparing a public release

The source archive produced by `python scripts/source-archive.py` is the publishable repository tree. Extract it and create a repository from that folder. The archive includes the native Mac application, portable Windows/Linux application, tests, resources, build scripts, CI, GPLv3 and branding/third-party terms. `SOURCE-MANIFEST.sha256` records every included file. No GitHub repository or public release is created automatically by this project.

Do **not** upload the entire local working directory without inspecting ignored files. `.build/`, `dist/`, environments, local card files and the unknown-license supplied RF reference script are excluded. All original Quadband source is included. Default Mac builds omit the private script and hide its export button. Independent ACS controls and the discussion link remain available.

1. Run the tests and native builds on the target systems. The workflow runs automatically after the source tree is pushed and provides Windows, Linux, Mac and source artifacts in the Actions run. It does not publish a release or modify cards.
2. Run the reader validation matrix in `VALIDATION.txt` on Windows and Linux. Test writes only against intended expendable targets. Record failures and firmware differences. Do not label untested paths as hardware-verified.
3. Review `dependencies.json` and the bundled license/notice directories. For binary distribution, supply the required corresponding dependency source and any LGPL relinking materials. Match the versions actually bundled: obtain Python source, matching PySide/Shiboken and Qt source archives (including bundled Qt third-party sources), and source distributions for hidapi, pyscard, Bleak and platform dependencies. Publish those alongside the binaries or use another license-compliant provision method. PySide source archives: https://download.qt.io/official_releases/QtForPython/pyside6/ . Qt source archives: https://download.qt.io/official_releases/qt/ . The application's embedded source archive alone does not cover third-party library obligations.
4. Attach the full source archive and native artifacts to a release. The native Mac zip includes the app source archive; Windows/Linux directory packages also include it. Python wheels are installable with Python, not standalone executables.
5. Optional public signing: sign/notarize the Mac app with your Developer ID and sign Windows executables with your publisher certificate. Credentials must stay in private CI secrets; none are included. Linux packages need no signing to run but release checksums/signatures are useful.

Versioning: the current release is 1.0.1. Update `desktop/pyproject.toml`, `desktop/src/quadband/__init__.py`, `Resources/Info.plist`, archive/build labels and validation notes together. Binaries built by PyInstaller are OS/architecture specific. Build Linux on the oldest supported distribution; the present workflow targets Ubuntu 24.04. Keep the full runtime folder with the executable.

The native Mac build is ad-hoc signed for local use. Build artifacts are release candidates until native target-system tests, dependency-source provision and optional signing are complete.
