Nordic UART UUIDs and subscription-before-command behavior were cross-checked; its retry, DFU and reader-security-setting paths were not imported. Existing desktop BLE transports were extended rather than replaced. Fresh bounded scans require explicit peer selection; disconnects invalidate shared HF/LF availability, and unconfirmed cleanup blocks transport reuse. Identity/model/capability validation remains separate from GATT readiness.

The Zero adds an unprivileged Python BlueZ/Bleak helper over private inherited, versioned, length-bounded pipes. Opaque discovery tokens retain actual BLEDevice objects; a selected-peer-only Agent1 handles local masked passkeys on the same D-Bus connection that requests pairing, without replacing the default agent. The C++ worker retains protocol/reader ownership. Verified disconnect is required for USB/BLE handover; helper death or unconfirmed active cleanup latches restart-only quarantine. The static C++ executable now has documented package-level Python, BlueZ, Bleak and D-Bus runtime dependencies; no root GUI, root pip or daemon/USB-role reconfiguration is installed.

CoreS3 adds a selected NUS central alongside the existing desktop peripheral. Link roles, peer/challenge epochs, authorization and persistent bond slots are isolated; legacy desktop bonds migrate conservatively and ambiguous/orphaned state fails closed. Secure Connections/MITM, bonding and 128-bit keys remain required. New GATT operations reuse the existing guarded Ultra session, actual command list and original-mode restoration. Idle-only transport changes advance the generation even when capabilities match. Failed restoration or teardown quarantines reuse; BLE does not authorize VBUS, and no operations reconnect or replay automatically.

Integrated validation passed 477 portable tests with two hardware opt-ins skipped, configured Ruff, 175 native Swift tests with five hardware opt-ins skipped and no failures, all 13 Zero sanitizer/CLI/UI executables, 43 release-helper tests and 17 protocol/source tests. CoreS3 production central and peripheral callbacks compile against deterministic GATT/FreeRTOS/NVS mocks under ASan/UBSan; scoped bonds/migration, dual-role routing, PIN expiry/fresh-press, wrong peers, fragmented replies, queue pressure and no replay are covered. Existing firmware policy, UI/compositor and seven standalone suites passed, including 19 NDEF and 216 LF golden encodings. Web-export checks passed 11 tests plus 16 subtests.

Both real Bleak 0.22.3 and 3.0.2 Python APIs and real dbus-fast Agent1 method signatures were checked in isolated environments without connecting to D-Bus or Bluetooth. Helper/package tests use fake peers/buses, including same-bus pairing, stale PINs, bounded IPC, absolute transaction deadlines, helper death and failed cleanup. Actual static Linux ARM64 and pinned ESP-IDF production builds passed. The CoreS3 application is 1,329,280 bytes in the unchanged 1,536,000-byte application partition, leaving 206,720 bytes; this is flash headroom, not measured two-link runtime heap.

No device was installed, flashed, Bluetooth-scanned, paired or used for RF/card operations during this implementation. Physical macOS/Windows/Linux/Zero/CoreS3 pairing, real two-link heap/coexistence, keyboard/framebuffer acceptance and interrupted-reader behavior remain separate gates. Simulator screen capture was unavailable; automated LVGL/UI tests are not a visual hardware pass. Windows packaging is locally assembled/static-checked, not Windows-executed; the portable wheel/source is not a native Linux frozen executable. Published v1.1.1 and historical feature branches are unchanged; no commit, push or publication was performed.

## Version 1.2.1 release portability correction

After explicit release authorization, the integration was committed and tagged v1.2.0. Native Linux CI exposed GCC warnings treated as errors: clearing a default-initialized command structure with memset, a misleadingly indented fixture loop, and a copied range-loop pair in a Zero test. Version 1.2.1 uses explicit volatile byte wiping for the transient command/passkey and separates/binds the test expressions without removing cases or relaxing warnings/security. The incomplete v1.2.0 release was withdrawn to draft; its tag remains unchanged. The corrected immutable release requires fresh native CI validation before asset publication.

The corrected c94fdae commit passed all seven native build jobs, including Windows, Linux, macOS, CoreS3 and the GNU host regressions. The separate Zero job passed its sanitizer checks, real ARM64 cross-build and package generation, then exposed a missing Bleak dependency in that job's Python test environment; its independent 0.22.3/3.0.2 runtime jobs passed. The released Zero package was independently cross-built from the same tagged sources with payload/source hashes and all 24 helper/package tests verified on both runtimes. A subsequent automation-only main change installs the pinned test dependency without moving the v1.2.1 tag or changing its application code.
